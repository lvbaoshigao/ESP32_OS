# 自研内核功能增强需求说明书


## 一、概述

本文档基于现有自研内核，在**不依赖任何现成操作系统框架**（如ESP-IDF、FreeRTOS、Linux内核等）的前提下，从底层实现各功能模块的更新与增强。所有代码需直接操作硬件或使用内核内部抽象层，以`doc.md`为核心准则进行开发。


## 二、闪存分区管理（`part`命令）

### 2.1 功能需求

实现闪存分区的完整管理能力，支持以下分区布局：

```
| boot | kernel | tools | user |
```

### 2.2 命令规范

| 命令 | 功能描述 |
|------|----------|
| `part -list` | 以树形结构列出所有分区及其信息 |
| `part -add <partname>` | 新增一个分区 |
| `part -add <partname> -f <name0> -b <name1>` | 在`name0`之后、`name1`之前添加分区（`-f`与`-b`顺序可互换） |
| `part -del <partname>` | 删除指定分区 |
| `part -help` | 显示帮助信息 |

### 2.3 安全约束

- **系统分区保护**：`boot`、`kernel`分区为系统分区，删除前必须验证**Root权限**
- **双重确认机制**：无论何种用户角色，删除系统分区前须**两次输入确认**（键入两遍`Y`），每次确认均需明确提示操作风险
- **分区存在性校验**：执行`-add`命令时，若`-f`或`-b`指定的参考分区不存在，则禁止操作


## 三、网络协议栈

### 3.1 核心网络概念

实现以下网络基础概念的底层支持：

| 概念 | 说明 |
|------|------|
| **IP地址** | IPv4地址的表示、存储与配置 |
| **MAC地址** | 硬件地址的读取与管理 |
| **DHCP** | 动态主机配置协议客户端，支持从DHCP服务器自动获取IP地址、子网掩码、默认网关及DNS等网络参数 |

### 3.2 驱动实现

- **Wi-Fi驱动**：从底层实现Wi-Fi模块的初始化、扫描、连接、断开等基础功能
- **蓝牙驱动**：从底层实现蓝牙模块的初始化、设备发现、配对与数据传输


## 四、MCP（Model Context Protocol）调试工具

### 4.1 功能定位

实现**内核级MCP工具**，使AI助手能够通过标准化协议进行内核调试。MCP提供多层次的调试能力。

### 4.2 核心能力

- 通过MCP工具调用暴露内核调试接口
- 支持读取内核运行状态（变量、寄存器、内存等）
- 提供断点设置、单步执行、变量检查等调试功能
- 与AI助手（如Claude等）集成，实现自然语言驱动的调试交互


## 五、命令系统优化

### 5.1 命令合并与重构

对现有命令结构进行审查，识别功能重叠或可合并的命令，按以下原则优化：

- **功能内聚**：相关功能聚合为单一命令的子命令
- **命名一致**：统一命令命名风格（如统一使用`-`前缀参数）
- **减少冗余**：删除功能重复的命令

### 5.2 `help`命令精简

`help`命令**仅展示关键命令**，例如：

```
ls, mkdir, help, part, network, command, export, ...
```

详细帮助通过各命令的`-help`参数获取。

### 5.3 命令`-help`参数检查

**所有命令**必须实现`-help`参数，输出内容包括：

- 命令用途简述
- 可用参数列表及说明
- 使用示例（如适用）

### 5.4 命令列表管理

| 命令 | 功能 | 备注 |
|------|------|------|
| `command -show` | 列出当前所有可用命令 | 建议合并至`help`或独立为`cmd -list` |
| `command -del <cmdname>` | 删除第三方命令 | **系统内置命令不可删除**；建议合并至`cmd`或`unregister` |

> **建议**：将`command -show`与`command -del`合并为统一的`cmd`命令族，如`cmd -list`和`cmd -unregister <name>`。


## 六、环境变量与导出

### 6.1 环境变量系统

实现内核级环境变量管理，支持：

- 变量的**设置**与**读取**
- 变量的**持久化**（可选）
- 变量作用域管理

### 6.2 `export`命令

参考Linux实现，`export`命令功能如下：

| 用法 | 说明 |
|------|------|
| `export VAR=value` | 设置并导出环境变量 |
| `export VAR` | 将已有变量导出至子进程环境 |
| `export -n VAR` | 删除（取消导出）指定环境变量 |

导出的变量对后续执行的命令/脚本可见。


## 七、命名规范

- **PKI相关命令**：统一使用**小写**（如`pki`）
- 所有命令参数建议统一风格，如统一使用`-`前缀（`-help`、`-list`、`-add`、`-del`等）


## 八、software目录实现

根据`software`目录下的提示词（prompt）完成相应功能的代码实现，确保与内核整体架构一致。


## 九、优化原则总结

1. **保持原意**：所有功能需求不变，仅优化表述结构与专业性
2. **参考业界实践**：借鉴成熟嵌入式系统（如U-Boot、FreeRTOS CLI、Zephyr等）的命令设计规范
3. **严禁随意添加**：不引入原文未提及的功能或概念
4. **结构清晰**：按功能模块组织，便于开发团队逐项实施
